Keep your monitoring next to the services it watches. When a new API ships, its uptime monitor and status page entry ship in the same pull request, get the same review, and roll back the same way.

Databuddy works with infrastructure as code tools through the same scoped API keys as the [HTTP API](/docs/api). Changes made in the dashboard stay visible: a refresh shows the drift, and the next deploy puts your code back in charge.

## Resources

### Available

| Resource | What you control |
|----------|------------------|
| Uptime monitors | URL, check frequency, timeout, cache busting, paused state, linked website |
| Status pages | Name, slug, description, logo, favicon, links, theme |
| Status page monitors | Which monitors appear on a page, display name, order, and what is hidden |

### Coming soon

| Resource | What you'll control |
|----------|---------------------|
| Uptime alerts | Slack, email, and webhook destinations for monitor outages |
| Websites | Tracked websites, their domains, and tracking settings |
| Feature flags | Flags, rollout percentages, targeting rules, and variants |
| Flag target groups | Reusable audiences for flag targeting |
| Goals | Page view and event conversion goals |
| Funnels | Funnel steps and filters |
| Short links | Links, destinations, and folders |
