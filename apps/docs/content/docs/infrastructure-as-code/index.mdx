import { Callout, Card, Cards } from "@/components/docs";

Keep your monitoring next to the services it watches. When a new API ships, its uptime monitor and status page entry ship in the same pull request, get the same review, and roll back the same way.

Databuddy works with infrastructure as code tools through the same scoped API keys as the [HTTP API](/docs/api). Changes made in the dashboard stay visible: a refresh shows the drift, and the next deploy puts your code back in charge.

## Resources

| Resource | Status | What you control |
|----------|--------|------------------|
| Uptime monitors | Available | URL, check frequency, timeout, cache busting, paused state, linked website |
| Status pages | Available | Name, slug, description, logo, favicon, links, theme |
| Status page monitors | Available | Which monitors appear on a page, display name, order, and what is hidden |
| Uptime alerts | Coming soon | Slack, email, and webhook destinations for monitor outages |
| Websites | Coming soon | Tracked websites and their settings |
| Feature flags | Coming soon | Flags, rollout rules, and variants |
| Short links | Coming soon | Links, destinations, and folders |
